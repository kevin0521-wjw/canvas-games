# 单文件 Canvas 游戏档案

六款 **单文件 HTML5 + Canvas 2D** 游戏（其中两款同题材、两条实现路线），外加一份**初版存档**。零第三方库、零图片、零音频素材 —— 飞船、角色、粒子、星空、符纹全部由代码在 `requestAnimationFrame` 里实时绘制。每个游戏就是一个 `index.html`，双击即玩，不需要服务器。

**在线入口 → <https://kevin0521-wjw.github.io/canvas-games/>**（版本档案首页，按交付顺序列出全部游戏与历史快照）

| 深渊回响 | `WASD` / 方向键 | `J`（自动瞄准） | `Shift` 翻滚　`E` 开箱　`1/2/3` 选升级 | `Q` / 面板按钮 | `T` / 面板按钮 |

| 符箓灵弹 · 元素阵 | `←→` 走位　`↑↓` 瞄准 | `空格` 发弹（带元素） | `1-4` / `Q` 换元素　`P` 暂停 | `E` / 面板按钮 | `T` / 面板按钮 |

> **AI 开关为什么不再是 `A`**：五款统一支持 WASD 之后，`A` 得用来「左移」——
> 原来按住 A 走位会顺手把 AI 反复开关。星屑与星轨改到 `E`，深渊的 `E` 已被「开箱」占用，改到 `Q`。

**五款都同时有 AI 接管与二倍速。** 这两件事在判据里是可验证的，不是"做了个开关"：

- **AI 不作弊**：它只写方向键的布尔值，走的是和玩家**完全同一套**移动物理。判据逐项比对开关前后的判定半径 / 擦弹半径 / 无敌帧 / 移速，并实测单帧位移不超过玩家移速。
- **二倍速不改规则**：一律用**固定步长累加器**（每帧多跑几次 `update(1)`），绝不写 `update(dt*2)`。判据用「20px/帧 的探针弹在 2× 下仍然命中 2.8px 判定点」来证明没有穿透。

触屏也能玩：把手指当方向键拖，按钮在屏幕上。

## 目录结构

```
index.html                  ← 版本档案首页（由 _build_site.js 生成，别手改）
manifest.json               ← 游戏与版本的元数据（顺序、简介、版本记录都在这儿）
_syntaxcheck.js             ← 语法自检：编译全部 script 块与判据（游戏清单从 manifest 读）
_contrastcheck.js           ← 配色自检：从生成产物里读回颜色算 WCAG 对比度（19 项）
_run_all.js                 ← 一键并行回归全部游戏，输出到 _logs/（会先跑上面两个静态检查）
_snapshot.js                ← 把当前版本留档到 versions/<日期>/
_build_site.js              ← 用 manifest + _logs 生成 index.html

<游戏目录>/
  index.html                ← 唯一源文件，整个游戏都在这儿
  verify/smoke.js           ← 冒烟判据（headless Edge + CDP）
  verify/diag.js            ← 运行时诊断脚本（按模块变量名逐个 eval）
  PROVENANCE.md             ← 仅初版存档有：来源、抓取时间、字节数、md5

versions/<日期>/<游戏>/       ← 历史快照，只增不改
versions/<日期>/_logs/        ← 该版本的回归日志（证明"这一版当时验过、验了几项"）
_logs/<游戏>.log             ← 最近一次回归的完整输出（首页上的断言数从这里读）
```

## 跑测试

```bash
node _syntaxcheck.js     # 先编译一遍，拦住低级语法错（秒级）
node _contrastcheck.js   # 配色对比度（改过 CSS 才需要单独跑；_run_all 里也会带一遍）
node _run_all.js         # 全部并行回归，结果写进 _logs/（内部先跑上面两个静态检查）
node _build_site.js      # 断言数会自动填进首页
```

单跑某一款：

```bash
cd <游戏目录> && node verify/smoke.js index.html __SL
```

判据跑在**真实浏览器**里（headless Edge + CDP，WebSocket 直连、不依赖 puppeteer），不是 Node 里搭 DOM stub —— Canvas 的实际绘制路径（渐变、shadowBlur、ellipse 兼容）只有真浏览器能暴露。

## v1.4.0 这一轮改了什么

六件事：**元素反应要有决策**、**降难度要给解法**、**加 BOSS 与关卡**、**弹幕要能读清**、**UI 不溢出**、**日志与版本跟上**。

### 1. 元素反应从「一张倍率表」变成「一条链」

原来的风是万金油：打谁都是 `扩散 ×1.25`，等于没有选择。现在拆成三条分支，副作用完全不同 ——

| 攻击元素 × 目标 | 反应 | 倍率 | 副作用 |
|---|---|---|---|
| 火 × 水 | 蒸发 | **×2.0** | 纯伤害，最高的单体收益 |
| 火 × 雷 / 雷 × 火 | 超载 | ×1.5 | 攻击点半径内**范围爆炸**，一次清一片 |
| 雷 × 水 / 水 × 雷 | 感电 | ×1.3 | **同排连锁**，整行一起掉血 |
| **风 × 火** | 燎原 | ×1.45 | **同排点燃**，持续烧 |
| **风 × 水** | 浸润 | ×1.2 | **符阵整体减速**，买时间 |
| **风 × 雷** | 雷暴 | ×1.4 | **同列麻痹**，硬控 |
| 同元素 | — | ×1.0 | 不反应 |

而真正的变化在**第三层**：反应结束后，被打的符块会被**染成攻击元素的颜色**（`transmute`）。于是「火 → 水 → 雷」可以连着打三次反应，玩家会开始算「先染哪一块、下一发换什么元素」。倍率表只提供数值，染色提供的是**路线**。

### 2. 降难度不是削敌人，是给玩家多一个动作

六款都降了（含并入的「元素阵」），但原则一致：**加解法，而不是减威胁**。符箓灵弹上最典型的三条 ——

- **元素爆发**（`E`）：能量满 100 时清掉场上所有符矢 + 对全屏符块做一次带反应的攻击 + 把墙推回 34px。它把「被压死」从必死局变成一个可以主动换气的时刻。
- **灵弹可以击落符矢**：以前 BOSS 的弹只能躲，现在拿球撞上去能打掉，还回 6 点能量 —— 进攻本身就是防守。
- **越线后墙回退 84px**：漏一排仍然是扣一命，但不会立刻连锁崩盘，给 2 秒喘息。

其余数值：符盘宽 52 → **58**、命 3 → **5**、符块血 `10+2n` → **`8+1.3n`**、墙速 `10.5+0.55n` 无封顶 → **`min(13, 7.6+0.32n)`**、阵间喘息 1.15 → **1.9 秒**。
另外四款：星屑弹速 ×0.86 / 判定 3.5 → **2.8px** / 擦弹 24 → 30 / 残机 3 → 4；深渊血量成长 ×0.64、玩家血 3 → 4；星轨敌机血 ×0.85；初版升级 22 秒一级、上限 10。
并入的「元素阵」：心 4 → **5**、墙速 `10.5+0.55n` → **`8.8+0.36n`**、符块血 `10+2n` → **`9+1.5n`**。

### 3. BOSS 与关卡：数据驱动，不是 `if (wave === 8)`

- **符箓灵弹**：`WAVES_PER_CHAPTER = 8`，`isBossWave(n) = n % 8 === 0`，BOSS 类型按 `chapterOf(n) % BOSS_KINDS.length` 轮换。三种符使的弹型分别是**扇形**（3 发，二阶段 5 发）、**环形**（5 发，二阶段 6 发 —— 必须是奇数才有缝钻）、**雷击**（0.85 秒收缩虚线圈预警，落地劈墙）。半血切二阶段时 `core.fireT = -24`，给半秒缓冲，避免玩家在切换动画里白挨一轮。
- **星屑符咒**：3 关 7 卡 → **5 关 10 卡**。
- **星轨 v2**：3 关 3 种 BOSS 弹型 → **5 关 5 种**（新增交叉螺旋、定点轰炸），`cards[].pattern` 数据驱动。
- **深渊回响**：BOSS 按 `depth % 3` 轮换（分裂 / 瞬移 / 残影），只在偶数层出现。
- **初版**：三阶段 → **四阶段**，14% 血以下进濒死形态（扇形 7 发、环弹 10 发但转得更快 —— 缝更多）。

### 4. 弹幕可读性：先看得清，再谈躲得开

- **去掉 `ctx.shadowBlur`**（符箓、初版）。它是全局合成器开销，弹幕一密就掉帧；改成「先画大一圈深色实心 + 再画本体」，视觉上等价、性能好一个量级。
- **速度三档描边**：`sp > 260 ? 2.4 : (sp > 140 ? 1.8 : 1.3)`。玩家一眼能看出哪颗先到，而不是靠试。
- **延迟弹加收缩警示圈**，把「随机挨打」变成「看得见的倒计时」。

### 5. UI：溢出是画布外的事，截图才看得见

- 符箓灵弹 HUD 重排成四行（命/阵数/分数 → 章节名/元素条 → 徽标/能量条 → BOSS 血条），BOSS 提示条从 `top:38%`（正好压在符阵墙中间）挪到 `top:74%`。
- 星屑 / 星轨 / 深渊的状态条从 `white-space:nowrap` 改 **`flex-wrap:wrap` + `max-width:calc(100% - 10px)`** —— 关卡从 3 变 5、项名变长之后，原来会向两侧溢出到画布外。
- 深渊受击渐晕上限 0.42 → **0.26**、血雾层 0.14 → **0.05**。原来整间房长期偏紫红，分不清「这层就是这个色调」和「我快死了」。

> 这几条都是**断言全绿、看截图才发现**的：判据量的是数值和状态，量不到「字跑到画布外面去了」。

### 6. 站点级共性修复（大屏 / 高分屏 / 键位）

- **缩放上限 1.15 → 2**：原来 `fit()` 把画面锁死在 1.15 倍，22 寸屏上游戏永远只有约 550px 宽，四周全是黑边。封顶的应该是「逻辑尺寸」而不是缩放比例。
- **补上 HiDPI**：`cv.width = W × min(dpr, 2)` + `ctx.setTransform(dpr,…)`。不做这件事，2x/3x 屏上画布被 CSS 拉大，符纹的细线和 1px 描边全部发虚 —— 而这轮刚把「弹幕可读性」当成重点，字糊了等于白改。
- **五款统一「方向键 + WASD」**，字母大小写都映射。第三点尤其阴险：按住 `Shift`（精确/翻滚）时浏览器给的 `e.key` 是**大写**，只映射小写 ⇒ 「Shift + 移动」整体失效，而单按移动又正常，很容易被当成「Shift 不好用」。
- **副作用要一起处理**：`A` 一旦让位给「左移」，原来绑在 `A` 上的「AI 接管」就会在每次往左走时被反复开关。星屑 / 星轨改到 `E`，深渊的 `E` 已被「开箱」占着，改到 `Q`。

### 7. 同题材的并行实现也并了进来

这轮有两条线同时在做「符箓灵弹 + 元素反应」，做法不一样，都留下了：

| | 符箓灵弹 · 巧阵（`talisman-pinball`） | 符箓灵弹 · 元素阵（`talisman-array`） |
|---|---|---|
| 灵弹 | 接球反弹，灵弹本身不换元素 | 直接发弹，灵弹带元素 |
| 反应落点 | 倍率 + 副作用 + **染色连锁** | **范围 / 传播 / 持续**（燃烧蔓延、蒸发放湿、扩散染色） |
| 关卡 | 每 8 阵一章，三种符使轮换 | 3 关 × 8 阵，固定三阶段符核 |
| 额外压力 | 符矢可击落、元素爆发 | **护甲块**：直接伤害被减免，只能靠反应破 |
| 判据 | 36 项 | 18 项（本轮补齐，原先没随仓库留档） |

并入时还发现并修掉了两件事：

- 那一版 `draw()` 里仍留着 `g.translate(rnd(-sh, sh)…)` 式震屏 —— 而 v1.3.0 已经按「不要视觉污染的抖动」全站移除，属于回归，已删。
- 它的数值还停在 v1.3.0 的水位（心 4、墙速 `10.5+0.55n`、符块血 `10+2n`），本轮按同一条降难度口径调到心 5、`8.8+0.36n`、`9+1.5n`。

> 同一题材留两份实现不是犹豫不决：**它们验证的是同一个设计问题的两种答案** —— 反应的价值到底在「倍率」还是「改变战场元素分布」。留档比删掉更有说服力。

### 为什么判据要写得这么琐碎

这个仓库里最值得留档的不是游戏，是那批「**断言全绿但游戏其实不可用**」的案例。举几个真实发生过的：

- **升级池里 5/14 项完全无效** —— 升级函数收到了「武器数值表」却去写玩家身上的字段，于是玩家选了升级、面板也显示 Lv+1，**数值一点没变**；升到满级后该条目还会从池里消失，等于永久丢掉一个选项。原来的判据只验了其中一项（恰好是写对的那个），所以是全绿的。
- **对象漏一个布尔字段** —— `bullets.push({...})` 少写 `alive: true`，末行 `bullets.filter(b => b.alive)` 当帧把它全清掉。症状是「按键有反应但场上恒为 0 颗弹」，而另外 19 条断言全绿。**`filter` 不会校验字段存在性，`undefined` 就是假值，静默删除、不报错。**
- **秒 / 帧单位混用** —— `timeLeft -= dt`（dt=1/帧）而配置里 `time: 40` 是按秒写的，于是 40 秒的符卡实际只有 0.67 秒，而 HUD 显示「T 40s」，**数字完全对得上**。
- **`lives < 0` 应为 `<= 0`** —— 残机减到 0 时判定不触发，HUD 显示「残 0」却还能一直玩下去。这条是**看截图肉眼发现的**，断言全绿。
- **永不成立的条件** —— `mkEnemy` 忘了初始化 `patT`，`e.patT -= dt` 得到 `NaN`，而 `NaN <= 0` **恒假**，于是杂兵从开局到结束一发子弹都打不出来。不报错、不崩溃、游戏照跑，只是「整个杂兵阶段零威胁」。
- **数组下标少减 1** —— `STAGES[run.stage]` 应为 `[run.stage - 1]`。后果是最后一关取到 `undefined`、读 `.cards` 抛 TypeError，**游戏永远无法通关**。31 项断言全绿都没抓到，因为没有任何一条走到「最后一关的 Boss」。
- **唯一的调用点被守卫挡住** —— `spawnBoss()` 全代码只有 `updateWaves` 里一个调用点，而 `updateWaves` 又被 `if (!boss && !run.noSpawn)` 挡着。测试里只要顺手设了 `noSpawn = true`，Boss 就**永远不出现**；症状是「12 张符卡全部进不去」，而游戏本身完全正常。
- **独立的 `requestAnimationFrame` 循环** —— 开箱弹面板用了自己的一条 rAF 链，而测试的 `freeze()` 只停主循环。于是测试里存在两个时钟，判据时而吃到面板抢走的 `choosing` 标志、时而吃不到 → **随机失败**，看起来像「机制坏了」。
- **「点不到」不等于「不在屏幕内」** —— 布局判据里 `getBoundingClientRect()` 说按钮在视口内，但**实际点不动**：外层 `overflow:hidden` + 容器无高度上限 = 元素永久够不到。所以布局判据必须用 CDP 固定视口 + `elementFromPoint()` 命中检查 + **真实鼠标事件**派发，才算验过。

因此判据里有一批看起来多余的规矩：每条需要 `step()` 的判据都自己开一局并清掉全部早退守卫；对象少字段要用逐帧采样定位；UI 上写死的数字要问一句「这是算出来的还是写死的」。详见 `verify/*.js` 里的注释 —— 那些注释记的是**当时错在哪**，比代码本身更值钱。

### 探针自己会错，而且错得比游戏还理直气壮

另一类更隐蔽的坑：**测量工具给出一个「看起来像游戏有 bug」的结论，实际是探针自己的问题**。真实发生过的三次：

| 探针报的现象 | 真实原因 |
|---|---|
| 「六张符卡全部打满限时打不掉」 | 探针把玩家钉在 y=240 不动，而 Boss 的 y 在 ±170 间摆动 —— **探针没有瞄准** |
| 「三关敌舰数全是 0」 | 探针自己设了 `noSpawn = true`，而那正是关掉刷怪的开关 |
| 「补给舱掉率 0%（600 次击杀）」 | `mkShot(x, y, off, dmg, spd, …)` 写成了 `(x, y, 0, 8, 999, 0)` —— **把速度当伤害传**，弹速 999px/帧一帧飞出场地，敌人一枪没中，而分母却按 600 次算 |

三条都差点直接拿去改游戏数值。因此定了一条规矩：**任何比率型指标，分母必须是被验证过的事件数，不是循环次数**；以及**探针报出的每个数字，都要先回答「谁定义的」**。

同类的还有「判据自己有缺陷」，三个真实例子：

- **测量项与被测项耦合** —— 「AI 会躲弹」这条判据把玩家 warp 到 x=300 再读 `ax`，但站位项在那个位置就给了 `dx = -3.0`：**哪怕空无一弹，AI 也会往左**（它想回射击位）。于是这条判据永远绿，却什么也证明不了。修法是把玩家放到射击位本身让站位项≈0，并加一条空场基线断言。
- **测的东西贡献恰好为零** —— 修好上面那条之后又红：测试弹放在玩家正右边同高度、正朝玩家飞来，最近接近点 `cx/cy` 都≈0，躲避项里 `cx / d = 0 / 0.001 = 0`。得换成**斜掠弹**（有明确最近点方向）才真正测到东西。
- **把统计事实当硬指标** —— 「AI 活满 60 秒」看起来很合理，但弹幕全是 `Math.random` 生成的，实测存活单轮从 42 秒到 150 秒都出现过，阈值定在哪都会有一部分种子落到线外。改成 **5 轮取中位数** + 与「放着不管」的倍率对比。

### 判据脚本自己的两个坑（都很贵，都踩过）

**① 别让「收尾」有机会拖住结论。** 判据跑完后要关浏览器、删临时 profile。原顺序是「收尾 → 打印结论 → 退出」，而在这台机器上删一个浏览器 profile 实测在 **0.9s ~ 170s** 之间大幅波动（Node 的 fs 删除被 safe-delete 垫片接管，单文件约 565ms；而 `cmd rmdir /s /q` 只要 229ms，差 700 倍）。结论迟迟不交付，外面看到的就是「跑了十几分钟没输出」——先后被误判成「游戏测试太慢」和「AI 长循环卡住」，其实跟游戏一点关系都没有。
现在的规矩：**先打印结论，再做收尾**；收尾每步独立 `try` 且带时间预算；`process.exit()` 前要做一次 stdout 冲刷，否则 Node 会丢掉管道里没刷出的「✅ 全部 N 项通过」那一行 —— 而那正是档案页用来填断言数的唯一来源。

> 更进一步：删除耗时**本身就波动极大**（同一台机器上 `fs.rmSync` 另一次只要 14ms/文件），所以正确决策不是「找最快的删法」，而是**别让收尾拖住结果** —— 结论先落盘，收尾再慢慢擦。

**② 判据脚本必须自包含，别抽公共模块。** `_snapshot.js` 只复制 `<游戏>/index.html` 与 `<游戏>/verify/*.js`，一旦判据 `require` 了目录外的公共文件，归档出来的判据将来就跑不起来了。重复就重复。

**③ 「找到页面」不等于「页面加载完」。** 拿到 CDP tab 之后，原来一律 `await sleep(1500)` 然后直接查 `window.__XX`。页面慢一点就读到 `undefined`，报「暴露测试接口失败」—— 而游戏逻辑毫无异常。真实踩到过一次：全量回归里 touhou-danmaku 挂 2 条，`__DM` 的 `typeof` 是 `false`，日志里找不到任何一条游戏异常。

现在的规矩：轮询 `typeof window.__XX !== 'undefined'`，最多 20 秒。慢页面自然多等，快页面立刻进，总耗时不增加。

## 档案页配色：浅色主题 + 对比度判据

档案页原本是深蓝底（`--bg:#0a0c14`），2026-10-15 按「深色不好看」的反馈改成了浅色。

真正花时间的**不是**换背景色，而是这件事：

> **深色主题的强调色不能直接搬到浅色主题。**

原来的 `--gold:#ffc94a` 是按「亮色配暗底」挑的，放到白底上对比度只有约 **1.58:1**（`--cyan:#5ec8ff` 约 1.9:1）—— 换算过来就是「几乎看不见」。阴险的地方在于它**不报错、不崩溃**，页面看起来只是「有点淡」，很容易被当成设计风格放过去。所以浅色版本把整套语义色按白底重挑了一遍（`--gold:#96650a` / `--cyan:#0b6a9e` / `--jade:#0d7a52` / `--rose:#c12f47` / `--violet:#6247d0`）。

有了 `_contrastcheck.js` 就不用靠眼睛了：

```bash
node _contrastcheck.js   # 19 个「文字 / 背景」组合，正文 ≥4.5:1、大号字 ≥3:1
```

两个设计要点：

- **颜色从「生成产物」里读回来算**，不是从构建脚本的变量里读 —— 免得出现「脚本里写的好看、产物里是另一回事」。
- **判据自己也会错。** 第一版的选择器正则没锚定行首，查 `a` 时命中了 `.meta{` 里的那个 `a`，于是「普通链接」这一行读到的是 `--dim` 的灰（#5f6a83，判定为通过），而真正的 `a{color:var(--cyan)}` **从未被检查过**。锚定行首后链接读到 #0b6a9e、5.88:1。查找型判据要先证明「它真的读到了目标」，再谈结论。

顺带记两个**只在成品里才看得见**的产物级 bug（都由这轮改版暴露）：

- **页脚在自己的页面上显示成了字面量 `<br>`。** `manifest.footer` 里写的是真 `<br>`，生成时却跟正文一起走了 `esc()` → 变成 `&lt;br&gt;`，浏览器把它当普通文字画出来。修法是单独开一条只放行 `<br>` 与 `**粗体**` 的通道。
- **改上面这处时又当场写错一次。** 把 `esc(manifest.footer || '')` 换成 `footerHtml` 时漏了调用括号，插进模板的是**函数对象本身**（被字符串化成源码），页脚直接显示出一段 JavaScript —— 而构建不报错、控制台照打「✅ 生成 index.html」。

  → 因此 `_build_site.js` 加了**产物自检**：生成后扫描「只可能来自 JS 源码」的形态，命中即 `exit 1`。⚠️ 这条判据**改了三版才立住，每一版都是判据自己在误伤**：第一版按裸词扫（函数关键字、常量关键字、模块加载关键字…）→ 立刻把「记录这个 bug 的这一段说明」判成了错误，因为说明里天然要写这些词；第二版收窄成「关键字 + 跟随符号」仍被拦下一次（说明里写了模块加载关键字加左括号）；第三版只留中文句子绝不可能长成的形态才通过。

  → **教训：判据的词表只能取「正文里不可能出现的形态」，不能取「词」。**

## 版本留档

`index.html` 是唯一源文件，改一次就覆盖一次。所以每次改完跑：

```bash
node _snapshot.js          # 源码 + 判据 + 出处 + **当次回归日志** → versions/<今天>/
node _build_site.js        # 首页的「历史快照」区会自动列出，并带上那一版的断言数
```

快照只增不改，随时能回滚或对比「昨天那版还能跑、今天这版反而崩了」。
日志跟版本一起走是刻意的：只留源码的话，半年后你只知道「当时长这样」，
不知道「当时到底验过没有」。
