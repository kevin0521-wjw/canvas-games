版本时间线（按时间正序）

  • v1.0.02026-10-12当前
    四款游戏全部跑到判据全绿，并做了一轮跨游戏缺陷扫描与修缮。这是本档案的第一个留档版本 —— 此前 games/ 目录不在版本控制里，所以更早的状态没有快照可回填。
    • 四款游戏判据全绿（15 / 22 / 24 / 31 项）
    • ★ starlane-v2：14 项升级里有 5 项写到了没人读的对象上 —— 选了升级数值却一点没变，而且升满后该条目还会从池里消失，等于永久丢掉一个选项
    • ★ starlane-v2：残机归零不结束游戏（lives < 0 应为 <= 0），HUD 显示「残 0」却还能一直玩
    • ★ starlane-v2：X 键同时绑了副武器和炸弹 —— 放炸弹会顺手打出一发副武器，且 X 按下即被置 false，副武器永远只能单点
    • ★ 元气骑士 / starlane-v2：开箱弹面板用的是独立的 requestAnimationFrame 循环，freeze() 停不掉它 → 无头测试里有两个时钟，判据随机失败（元气版『按键触发翻滚』实测时好时坏）
    • ★ 符箓灵弹：tickLive 是自续 rAF 链，每点一次「再来一局」就多一条，多条链同时往同一个 DOM 写
    • 符箓灵弹：底部提示条写「空格 切换目标」，而空格实际是切换弹道；战符浮字显示的是累计上限而非本次增量
    • 弹幕版：提示条只写「← → 移动」，漏了上下方向键（竖向弹幕游戏不能上下走是致命的）
    • 元气版：注释里的房间尺寸停留在第一版的 6×5（实际已是 16×10）
    • starlane-v2：红色补给舱默认名是带前导空格的中英混排「 overclock 舱」；pl.fortune * 0 死代码；P.xup 死分支（Alt-Fire 永不触发）
    • 新增 11 条判据，覆盖此前完全没被验证过的链路：升级池逐项有效性、残机归零、掉落物拾取、四方向移动、副武器命中、按 E 开箱
    • 新增 _syntaxcheck.js 与 _build_site.js：前者先编译一遍所有 script 与判据（拦住模板字符串里混入反引号这类只会浪费一整轮回归的错误），后者生成本页
